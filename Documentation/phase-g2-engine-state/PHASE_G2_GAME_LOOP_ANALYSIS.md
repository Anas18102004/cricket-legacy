# Game Loop Analysis

## Host and renderer path

Android surface lifecycle enters the native renderer. `nativeCricketRenderFrame` in `src/main.c` advances mobile-input frame bookkeeping and exposes frame telemetry. The recording renderer accumulates draw/scene metadata and `rec_present_impl` computes a per-present coarse visual context before publishing it atomically. This path observes what was rendered; it does not identify the original gameplay state machine.

## Input path evidence

Touch handling in `src/main.c` maps Android touch events to `input_tap`, `input_tap_move`, and `input_tap_release`; virtual key actions call `input_key_dik`. `host/input.c` uses profile cursor coordinates to steer menu taps. The repository's upstream host input and DInput implementations are translation shims; no verified cricket match phase is returned by DirectInput polling. The harness `main.c` also contains Phase F progression/scripted inputs. Those frame-count stages are test scaffolding and are not original-engine state evidence.

## Search result

Translated functions and RTTI were inspected alongside `host/input.c`, `host/dinput.c`, `render_rec.c`, and the native entry points. Existing function inventory has autogenerated `f_XXXXXXXX` names and unknown calling conventions in many places. Names and call counts alone do not establish update semantics. No safe game-loop hook with a decoded state argument was found.

## Threading and ABI

The coarse renderer reader uses atomic builtins and an explicit validity bit; reset occurs on Android lifecycle interruption. It only transports an integer across the rendering/JNI boundary. The same source mechanism compiles for x86_64 and arm64-v8a, but does not prove the underlying game representation is stable across ABIs. No guest-memory pointer or inferred structure is dereferenced by this adapter.

## Conclusion

A renderer-level observer is currently the least invasive integration point available. A gameplay-state adapter is not yet justified. Recovering a state machine object requires identifying its live instance and decoded fields from exact translated code or symbols, then validating transitions interactively.
